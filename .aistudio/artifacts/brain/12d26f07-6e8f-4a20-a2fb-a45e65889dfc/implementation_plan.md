# Pulao AI — Production Multi-Agent Procurement & Corporate Bid Oversight Architecture

A production-ready upgrade plan to transform Pulao AI from a client-simulated prototype into an observable, streaming, multi-agent procurement verification platform built on real Model Context Protocol (MCP) boundaries, strict evidentiary grounding, bilingual Kenyan context (English & Kiswahili), reproducible reliability evaluations, and dual readiness for both **public-sector statutory procurement** and **private corporate RFP/vendor governance**.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> Review these architectural decisions before approving build execution. No source code has been modified.

- **Confirmed Non-Negotiable Invariant**: The agent prepares and verifies the evaluation dossier; **it never awards a tender/contract or finalizes a disqualification**. Every irreversible action remains locked behind a named human Evaluation Committee / Procurement Approval Officer sign-off gate.
- **Confirmed Zero-Unsourced-Flag Rule**: Every single risk flag, compliance failure, or price alert must cite an exact source (`document name`, `page number`, `section/annexure`, and `verbatim text snippet` or verified registry reference). Any ungrounded finding generated by an AI model is automatically rejected by a Citation Verification Guard before reaching reviewers.
- **Decision Gate 1 — Sovereign Open-Weights + Frontier Streaming Strategy**:
  - *Recommended Default*: Route all AI inference strictly through a backend Express API proxy supporting **two live execution backends**: (1) **Local Sovereign Open-Weights Engine** (connecting to a local Ollama/vLLM endpoint running Llama 3.3 for air-gapped Kenya Data Protection Act compliance, with transparent status if no local GPU daemon is attached in the current host), and (2) **Gemini 4 Hydrogen (`gemini-4-hydrogen`)** via server-side `@google/genai` with native token streaming, thinking-trace streaming, and structured function calling.
- **Decision Gate 2 — Statutory & KYB Registry Adapters (KRA, BRS, NSSF, SHA/SHIF, AGPO)**:
  - *Recommended Default*: Because live Kenyan government APIs require institutional mutual-TLS credentials not publicly bundled, replace all deterministic hash-seed tricks and bidder-name shortcuts with a **pluggable Registry Adapter backed by a persistent database registry table** (seeded with realistic test entities, expiry dates, and clear `"Simulated Registry Adapter — Pending e-Citizen/iTax Credentials"` provenance tags for 100% open-source honesty).
- **Decision Gate 3 — Bilingual Scope (English & Kiswahili)**:
  - *Recommended Default*: Add a global workspace & assistant switcher (`Auto-Detect`, `English`, `Kiswahili`), automatic prompt/document language detection, full UI translation dictionaries for core procurement workflows, and bilingual statutory/policy explanations in the selected language.
- **Decision Gate 4 — Dual-Sector Rulebook Mode (Public Sector + Private Corporate)**:
  - *Recommended Default*: Keep **Public Statutory Procurement (Kenya PPADA 2015 & OCDS)** as the default out-of-the-box competition configuration, while architecting the Policy Rulebook, Tax/KYB checks, and Price Benchmark Engine as **tenant-configurable rule packs** so private corporates (banks, telcos, NGOs, manufacturers, construction firms) can switch to **Corporate RFP & Vendor Governance** mode (custom internal policy thresholds, historical PO benchmarking, conflict-of-interest screening, and multi-tier Procurement Committee sign-off).

### 1. Overview & Core Concept

- **What It Does**: Pulao AI is an autonomous, multi-agent pre-audit, vendor due-diligence, and bid verification platform. It parses uploaded supplier PDF bid/proposal packets page-by-page, dispatches specialized verification agents across real MCP servers, streams live reasoning and tool traces like an AI Studio workbench, enforces page-level citation grounding, measures exact token/compute cost per run, and halts at a legally binding human sign-off gate.
- **Target Audience & Named Offices**:
  - *Public Sector (Competition Primary)*: **Ministerial / State Corporation Tender Evaluation Committees** (such as KEBS or County Procurement Evaluation Committees) executing Preliminary Responsiveness & Financial Benchmarking under Sections 41, 42, 79, 131, and 176 of Kenya's Public Procurement and Asset Disposal Act (PPADA) 2015.
  - *Private Corporate & NGO Sector (Commercial Expansion)*: **Enterprise Procurement, Internal Audit, and Vendor Risk Committees** at banks, telcos, FMCG/manufacturing firms, energy/infrastructure companies, and donor-funded NGOs conducting competitive RFPs, Know-Your-Business (KYB) compliance checks, historical price-inflation audits, and kickback/collusion detection.
- **Key Value**: Compresses days of manual cross-checking across tax certificates, registration documents, and multi-hundred-line BOQs/schedules into a transparent, auditable, bilingual pre-committee brief—while eliminating hallucinated flags, protecting marginalized/rural suppliers from OCR false-positives, and guaranteeing human accountability.

### 3. User Experience & Visual Design

#### Key User Flows
1. **Organization Mode & Language Controls**:
   - Placed cleanly inside the workspace utility bar (keeping the top 3-zone header contract minimal), authorized admins switch rulebook context (**Public PPADA 2015** vs. **Private Corporate RFP**), and any user toggles language between **Auto-Detect**, **English**, and **Kiswahili**.
   - In **Auto-Detect**, the backend inspects the user's message or uploaded bid snippet and streams responses, statutory/policy explanations, and committee briefs in the detected language (including Kenyan procurement terms such as *Zabuni*, *Cheti cha Ushuru (KRA)*, *Kamati ya Tathmini*, and *Sheria ya Ununuzi wa Umma*).
2. **AI Studio-Grade Streaming Evaluation Console**:
   - Clicking **Run Evaluation Workflow** opens a live Server-Sent Events (SSE) stream.
   - **Collapsible Thinking & Planning Drawer**: Streams the Supervisor Agent's live plan, step transitions, retries/recoveries, and model reasoning tokens in real time (respecting `prefers-reduced-motion`).
   - **Live Multi-Agent Activity Rail**: Displays each specialist agent (`Intake & OCR`, `Statutory / KYB Auditor`, `Pricing & Collusion`, `Citation Guard`, `Report Drafter`) transitioning across `Queued → Running → Recovering → Verified → Gated`, with live elapsed milliseconds and cumulative token/cost counters.
   - **Streaming Findings & Bilingual Brief**: Renders plain-language English or Kiswahili executive summaries token-by-token as evidence is verified.
3. **Zero-Unsourced-Flag Citation Inspector**:
   - Every finding card displays a mandatory **Source Evidence Strip** (`Document Name · Page # · Verbatim Quote`). Clicking it opens the exact extracted page text alongside the finding.
   - If a PDF scan is degraded or low-confidence (e.g., skewed rubber stamp or image-only page), the UI routes it to an explicit **Confidence-Gated Human Review** banner instead of issuing an unfair disqualification flag.
4. **Observability, Cost & Defensibility Drawer**:
   - Live trace timeline showing every MCP server invoked (Custom vs Official Filesystem), full JSON inputs/outputs, retry/recovery branches, input/output/thinking tokens, exact run cost in USD and KES, and SHA-256 tamper-evident hash chain status.
   - One-click **Export Audit Dossier** (JSON trace + printable Evaluation Committee Report + CSV ledger) persisted across reloads.

#### Visual Identity & Design Discipline
- **Aesthetic Direction**: Authoritative civic-institutional & enterprise governance console—crisp neutral canvases paired with deep institutional navy surfaces and restrained semantic status accents.
- **Palette & 60-30-10 Discipline**: Preserve established semantic tokens (`--background`, `--card`, `--navy`, `--compliance`, `--caution`, `--critical`) with strict WCAG AA contrast ($\ge 4.5:1$), pairing color with explicit text labels and icons (never hue-only signaling).
- **Typography & Tabular Discipline**: Pair crisp geometric sans (`Plus Jakarta Sans` or `Manrope`) with `IBM Plex Mono` / `tabular-nums` on every financial figure (KES / USD), variance percentage, token count, latency metric, and SHA-256 digest.
- **Spatial & Anti-Slop Restraint**: Single-elevation cards (`1px` hairline borders, no nested card-in-card clutter, no thick left accent bars), clean unboxed metadata separated by `·`, single-line controls (`whitespace-nowrap`), and a strict 3-zone top header (`Brand` — `Nav Links` — `Primary Action`).

### 4. Key Product Decisions & Trade-Offs

- **Decision 1: True Multi-Agent Cyclic Orchestrator vs. Linear Script**
  - *Chosen Approach*: Replace the current fixed 8-step linear chain with a true **Supervisor + Specialist Multi-Agent StateGraph** featuring conditional edges (`addConditionalEdges`), tool-calling loops, retry/recovery branches, and confidence-based human escalation.
  - *Why*: Directly satisfies the 30-point "Agentic depth and MCP craft" standard—the agent inspects document quality first, plans needed tools, retries or falls back when scans or benchmarks are ambiguous, and only invokes mutating tools (`flag_procurement_disqualification`, `draft_evaluation_report`) after evidence clears verification.

- **Decision 2: Real Server-Side MCP Transport vs. In-Browser Simulation**
  - *Chosen Approach*: Introduce a Node/Express full-stack server entry point that spawns and communicates via real **Model Context Protocol (`@modelcontextprotocol/sdk`) stdio client transports** with **both**:
    1. Our Custom Procurement MCP Server (upgraded to query real indexed benchmark tables, configurable public/corporate rule packs, and persistent registry records—removing all `0.95 * declaredPrice` stubs and `APEX`/`VALID` cheat codes), and
    2. The official borrowed `@modelcontextprotocol/server-filesystem` server locked strictly to a sandboxed tender dossier workspace directory.
  - *Why*: Guarantees any developer cloning the repo can reuse the exact same MCP tool boundaries cleanly from any MCP host, and eliminates client-vs-server divergence.

- **Decision 3: Dedicated Citation Verification Guard ("Zero Unsourced Flags")**
  - *Chosen Approach*: Insert a deterministic + semantic **Citation Guard** stage before any finding is committed. Every finding must include a valid `document_id`, `page_number` ($\ge 1$ and $\le$ total pages), `section`, and `verbatim_quote` verified to exist in the extracted packet text or registry lookup payload. Ungrounded claims are quarantined internally (`unverified_claims_suppressed`) and never shown as a penalty against a supplier.
  - *Why*: Enforces the non-negotiable legal/ethical rule that an unsourced accusation against a supplier is worse than no flag at all.

- **Decision 4: Real PDF Parsing & Confidence-Gated Fairness**
  - *Chosen Approach*: Add real server-side PDF page-by-page text & metadata extraction (recording author, creator, producer, creation timestamp, page count, and character-density OCR confidence per page). Low-character / image-only / skewed scans trigger a low-confidence recovery path routing to human visual inspection rather than automated tax/registration failure.
  - *Why*: Fixes real-world PDF upload usability and prevents unfair disqualifications of rural/AGPO/SME suppliers submitting mobile-photographed certificates.

- **Decision 5: Honest Automated Evaluation Harness & Cost Telemetry**
  - *Chosen Approach*: Build an executable evaluation runner (`npm run eval`) testing 15+ realistic, uncurated bid scenarios (clean bids, expired KRA, struck-off BRS, +35% price inflation, -60% predatory undercutting, borderline 14.9% vs 15.1% edge cases, collusive shared PDF metadata, corporate RFP policy checks, Kiswahili bid schedules, prompt-injection attempts inside PDF text, and intentionally failing low-DPI image-only PDFs). Execute multi-trial runs ($N=5$) to compute and publish real pass rates, latency p50/p95, run-to-run variance, and exact cost per run.
  - *Why*: Satisfies the 15-point Evaluation & Reliability and 10-point Defensibility criteria with verifiable empirical benchmarks.

#### Data Model & State
- **Core Procurement Entities**: `tenders_ocds`, `market_price_index`, `bid_submissions`, `compliance_evaluations`, `committee_decisions`, `immutable_audit_logs`.
- **Multi-Tenant Organization & Rulebook Config (`organization_rulebooks`)**: Defines `org_id`, `sector_mode` (`public_ppada_2015` | `corporate_rfp`), `allowed_variance_pct`, `mandatory_checks` (e.g., KRA/BRS/NSSF/SHA/AGPO for public sector; KRA/KYB/ISO/Insurance/Beneficial Ownership for corporates), and `approval_quorum`.
- **Agent Run & Cost Ledger (`agent_runs`)**: Stores `run_id`, `org_id`, `tender_id`, `model_id`, `language_selected`, `language_detected`, `status`, `nodes_executed`, `retry_count`, `prompt_tokens`, `completion_tokens`, `thinking_tokens`, `estimated_cost_usd`, `estimated_cost_kes`, `latency_ms`, and `unverified_claims_suppressed`.
- **MCP Tool Call Traces (`mcp_tool_traces`)**: Persists every custom and borrowed MCP invocation (`run_id`, `server_name`, `tool_name`, `inputs_masked`, `outputs_masked`, `duration_ms`, `status`, `sha256_digest`, `human_gate_required`).
- **Statutory & KYB Registry Records (`statutory_register_records`)**: Database-backed simulated KRA, BRS, NSSF, SHA/SHIF, and AGPO test entities used transparently by the Custom MCP server instead of hash math or hardcoded pass shortcuts.
- **Normalized Finding Schema**: Every finding enforces `{ key, severity, category, title, detail, title_sw, detail_sw, citation: { document_id, document_name, page, section, verbatim_quote, confidence }, grounded: true }`.

#### Interactive Component & State Mapping
- **Sector Mode & Language Context**: Switches rulebook mode (`Public Statutory` vs `Corporate RFP`) and active locale (`en`, `sw`, `auto`), updating UI labels immediately and forwarding context + language directives to the streaming agent and assistant endpoints.
- **Streaming Audit Console**: Connects via `EventSource` / streaming `fetch` to the server-side stream endpoint, rendering live thinking tokens, node progression badges, recovery alerts, live MCP call feed, token/cost telemetry ticker, and final bilingual brief.
- **Bid Upload & Intake Handler**: Uploads real PDF bid packets to the sandboxed server dossier vault, extracts page-indexed text and PDF metadata via the server, and stores parsed page indices so downstream citations link directly to real page content.
- **Citation & Evidence Drawer**: Clicking any finding's citation chip opens the exact extracted page text and highlights the quoted evidence; low-confidence scans render a side-by-side manual verification prompt rather than a disqualification draft.
- **Human Sign-Off & Override Gate**: Remains locked until every grounded finding is individually upheld or overridden (minimum 20-character written rationale) and a named Accounting Officer / Procurement Chair records their role, ID, and statutory/policy affirmation.
- **Observability & Evaluation Dashboard**: Surfaces run-to-run reliability metrics, cost-per-run breakdowns across models, suppressed-unverified-flag counts, and hash-chain verification (`verifyChain()`).

#### Security, Fairness, Responsible AI & Open-Source Rigour
- **Security**: All `@google/genai` SDK calls (`gemini-4-hydrogen` with `ThinkingLevel` and `User-Agent: 'aistudio-build'`) run strictly server-side; zero API keys exist in client bundles. Uploaded PDF text is isolated inside delimiters as untrusted data with prompt-injection screening before reaching LLM prompts. Path traversal is blocked by `@modelcontextprotocol/server-filesystem` sandboxing, and Supabase RLS enforces tenant isolation for corporate accounts.
- **Fairness & Responsible AI**: Zero hardcoded bidder bypasses; equalized validation across AGPO and open bidders; confidence gating prevents penalizing rural/low-DPI mobile scans; **zero unsourced flags** enforced structurally; **zero autonomous awards** enforced by both backend gate checks and database sign-off constraints.
- **Open-Source Rigour**: Clean environment configuration templates, complete database schema/migration SQL scripts, removal of leftover duplicate directories, 100% honest documentation distinguishing implemented vs simulated external government registers, a repeatable `npm run eval` script with recorded multi-run reliability benchmarks, and a scripted 3-minute demo guide (showing both success and an intentional failure/escalation case).
